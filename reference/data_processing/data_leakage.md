# 数据泄漏检查（Data Leakage Check）

## 1. 适用问题

适用于所有需要估计模型泛化能力的预测、分类、排序和时间序列任务。凡是预处理、特征构造、样本匹配或调参可能使用验证期、测试期或预测时不可获得的信息，都应进行泄漏审计。

## 2. 不适用或需谨慎的情况

纯描述性分析不一定需要训练/测试划分，但仍须避免时间倒置和因果误读。随机划分对同一主体重复观测、空间邻近样本或时间序列尤其危险，因为样本并非独立。

## 3. 核心思想

模拟真实部署时的信息边界：对任一预测时点，只允许使用当时已经产生且可访问的数据。所有会“学习参数”的步骤，包括填补、缩放、特征筛选和目标编码，都必须在训练折内拟合。

## 4. 基本数学形式

真实风险为

$$
R(f)=\mathbb{E}_{(X,Y)\sim P_{future}}[L(Y,f(X))]。
$$

若验证集信息参与得到 $f$，验证损失便不再是对上述风险的独立估计，通常产生乐观偏差。

## 5. 输入、输出与主要假设

输入为字段产生时间、实体标识、数据血缘和完整建模管道；输出为可用特征清单、禁止信息、合法切分方案和审计记录。假设验证流程应近似最终应用场景。

## 6. 标准建模流程

写明预测时点与目标窗口；逐列标注可获得时间；识别目标派生、事后统计和重复实体；按时间、主体或组切分；把预处理封装进交叉验证管道；将最终测试集锁定到模型选择结束后只使用一次。

## 7. 评价与验证方式

比较随机切分与时间/分组切分的性能差距；删除可疑特征后复算；检查异常高分、近乎完美相关和训练/验证重复键；对完整流水线做外层交叉验证，而不是只验证最后的估计器。

## 8. 优点

泄漏审计通常比更换算法更能改善结果可信度，可防止比赛中“线下高分、真实失效”。明确时间边界也会提升论文可复现性。

## 9. 局限

隐蔽泄漏常来自业务流程，单靠相关系数无法发现；严格切分可能增加方差并降低表面分数，但这通常是更诚实的风险估计。

## 10. 华为杯常见用法

常见于跨年份预测、同一地区多期数据、滑动窗口特征和目标编码。应在方法部分说明切分单位、时间截点以及每项预处理在哪一折拟合。

## 11. 常见误用

全数据插补、标准化或 PCA 后再切分；使用目标期汇总量预测目标期；同一对象的近重复记录跨集合；反复观察测试集并调参；先筛选全数据显著特征再交叉验证。

## 12. Python 实现建议

使用 scikit-learn `Pipeline`、`ColumnTransformer`、`GroupKFold` 或 `TimeSeriesSplit`。保留样本 ID 和时间戳用于审计，但不要无条件作为模型特征；用断言检查训练与验证键、时间窗口和目标派生列。
