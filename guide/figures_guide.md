# 数学建模论文高质量图表指南

本指南给出一套适用于“华为杯”等研究生数学建模竞赛的八图证据链。八张图不是机械凑数要求；应根据赛题类型删减、替换或合并，但整篇论文至少要形成：

> 建模路线 → 数据结构与可信度 → 变量与机制 → 核心结果 → 误差验证 → 方法比较 → 稳健性 → 场景决策

其中，**图 1 先用 Scientific Illustrator 在 Draw.io 绘制，再用 Penpot 美化并交付**；图 3、图 8 继续优先使用 [Scientific Illustrator](https://github.com/icebird1998/scientific-illustrator)。图 2 优先采用脚本核验/提取数据，再用 LaTeX/PGFPlots 绘制；按赛题也可选择 Python/MATLAB/R 等脚本后端。其他数值图由可重建程序生成，必要时再做有限的矢量排版精修。

## 一、八张推荐图总览

| 编号 | 推荐图 | 主要回答的问题 | 主绘图工具 | 建议文件名 |
|---|---|---|---|---|
| 1 | 专业总体技术路线图 | 全文如何从数据走到结论，各子问题如何衔接？ | **Scientific Illustrator / Draw.io → Penpot** | `fig1_overall_workflow_penpot.pdf` |

| 3 | 关键变量关系或结构图 | 变量、模块、机制和约束之间是什么关系？ | **新版 Scientific Illustrator** | `fig3_variable_structure.pdf` |
| 4 | 直接回答赛题的核心结果图 | 题目最终要求的数值、方案、路径或布局是什么？ | 建模代码、GIS 或专业求解软件 | `fig4_primary_result.pdf` |

## 二、八张图的具体要求

## 图 1：专业总体技术路线图

### 目的

让评委在几十秒内看懂：题目输入是什么、各子问题解决什么、采用什么模型、结果如何传递、怎样验证、最终输出什么。

### 必须包含

- 原始数据、题目附件或业务输入；
- 数据检查、清洗和特征构造；
- 各子问题之间的真实依赖关系；
- 每个子问题的主模型或算法，不只写“建立模型”；
- 关键中间产物及其流向；
- 与本题实际执行相符的验证、灵敏度分析或回退节点（如适用）；
- 最终交付结果，如预测、评价、优化方案或决策建议。

### 版式建议

- 绘制前先搜罗和比较模板，再依据本题节点与依赖决定横向、纵向或分区阅读路径；
- 层级不超过三级，避免把论文目录直接画成流程图；
- 同类对象保持一致的语义颜色与线型，具体调色在本题中决定；
- 箭头表示真实的数据或逻辑依赖，不用装饰性箭头；
- 在框内写“方法 + 产物”，如“孤立森林检测异常值 → 清洗数据集”，不要只写“数据预处理”。

### 工具与交付

完整步骤见 [图 1 Draw.io → Penpot 工作流](figure1_guide.md)。先核对事实与依赖，**在创建 Draw.io 对象前搜罗并比较模板**；完成可编辑 Draw.io 初稿及 Gate A 后，再用 Penpot 原生对象美化，完成两轮 Gate B 检查。指南不预设具体模板或版式。Penpot 是图 1 的必经交付阶段。

文件统一放在 projects/<project_name>/figures/figure1/，至少包括：

~~~text
template_review.md
fig1_overall_workflow.drawio
fig1_overall_workflow_drawio.svg
fig1_overall_workflow_drawio.png
fig1_overall_workflow_penpot.svg
fig1_overall_workflow_penpot.pdf
fig1_overall_workflow_penpot.png
delivery.md                 # 事实源、Penpot 文件/Board 链接和验收记录
~~~

可复制给 Codex 的任务说明：

~~~text
[@scientific-illustrator](plugin://scientific-illustrator@scientific-illustrator-tools)
先读取本题题目、figure_handoff.md 与 results/verified/，列出图 1 的事实和真实依赖。
在创建任何 Draw.io 对象前，搜罗和比较至少三个相关模板，
将来源、适配性、可编辑性和选择理由写入 figures/figure1/template_review.md；
不足三个时记录检索过程，比较后可以选择空白画布，不预设模板和版式。

随后在 Penpot 以原生对象美化，核对事实、数字与箭头，完成两轮 Gate B 检查。
按 figure1_guide.md 交付 Draw.io 源文件、Penpot Board 链接及最终 SVG/PDF/2× PNG。
~~~

## 图 2：数据结构与关键分布图组

### 目的

用不超过三张数据图说明合格训练样本的结构、任务目标或类别标签的分布，以及由此产生的建模难点。图 2 展示数据事实，不提前展示模型成绩；数据质量、处理规则及处理前后的样本数量和关键质量指标，另用可追溯对照表呈现。

### 推荐内容

按赛题选择最能解释建模选择的一至三个主题，不机械凑满三张：

- 关键连续目标的分布、取值范围和分层差异；
- 分类目标的类别支持数、稀有类和不平衡程度；
- 场景覆盖、分组结构或不同观测粒度下的真实目标分布。

对于同时包含多个子问题的赛题，可让各子图分别解释一个子问题所面对的数据特征。直方图、箱线图、频数图或热力图等形式应由数据类型决定；不同单位和不同观测粒度应明确分开，不用一条共用轴强行比较。

### 必须标注

- 训练、验证或测试数据的准确范围；无真实标签的官方测试不能用于目标分布或性能图；
- 样本量、独立分组数、观测粒度、坐标轴和单位；
- 类别全集、稀有类、分箱或密度估计口径，以及零值或缺失值的处理；
- 直接比较的子图采用可比尺度；分层差异只作描述，不暗示因果效应；
- 图注中的数据文件与 Evidence ID，并与数据质量表格的处理口径一致。

### 工具要求

完整步骤见 [图 2 数据图工作流](figure2_guide.md)。绘图前比较至少两个相关图表示例并记录取舍；先用脚本核验已核实的数据、单位、类别及分组，再由 PGFPlots 或选定的其他脚本后端生成图。不得在 draw.io 中手工摆放数据点，也不得把逐行数据手抄进 TeX。保留提取脚本、生成数据和绘图源文件，完成至少两轮视觉检查，导出矢量 PDF/SVG 与至少 300 DPI 的 PNG。所有文件放在 `projects/<project_name>/figures/figure2/`。

## 图 3：关键变量关系或结构图

### 目的

把正文中的变量、模块、因果假设、约束和信息流压缩成一张清晰结构图，解释“为什么这样建模”。

### 适用形式

- 输入变量—状态变量—输出变量关系；
- 指标体系或层次分析结构；
- 结构方程路径、贝叶斯网络或因果假设图；
- 供应链、通信、交通、能源等节点—边网络；
- 模型内部模块和串联计算关系；
- 目标函数、约束和决策变量之间的作用结构。

若需要展示的是相关系数热力图、散点矩阵、SHAP 分布或联合密度，应由 Python/MATLAB/R 生成；Scientific Illustrator 负责的是**结构关系图**，不能用主观箭头冒充由数据识别出的因果关系。

### 必须包含

- 节点或变量的准确名称和必要符号；
- 不同箭头含义的图例，如作用、抑制、反馈、信息流；
- 外生变量、决策变量、状态变量和结果变量的分组；
- 与正文公式一致的方向和连接；
- 对尚未由数据证明的关系明确标为“假设关系”或“待验证关系”。

### 工具与交付

使用新版 Scientific Illustrator 制作，保留 `.drawio` 源文件，并导出矢量 PDF。

可复制给 Codex的提示词：

```text
[@scientific-illustrator](plugin://scientific-illustrator@scientific-illustrator-tools)
使用新版 Scientific Illustrator，在实时 draw.io 中设计数学建模论文的关键变量关系/模型结构图。
严格依据我提供的变量表、数学公式和模型接口，先区分输入变量、决策变量、状态变量、约束和输出，
再规划分组、层级和连接线。不得自行增加因果关系；假设关系必须使用与已验证关系不同的线型并配图例。
所有节点、文字、箭头和图例保持可编辑，避免交叉连线和含义不明的装饰元素。
完成后保存为 fig3_variable_structure.drawio，并导出矢量 PDF 和宽度 2000 px 的 PNG。
```

## 图 4：直接回答赛题的核心结果图

### 目的

用一张图直接回答赛题，而不是只说明模型性能。评委应能从图中读出最终数值、方案、路径、布局、排序或时空分布。

### 按题型选择

| 赛题类型 | 推荐核心结果图 |
|---|---|
| 预测与时间序列 | 实际值、预测值、预测区间和关键事件 |
| 路径规划 | 地图上的最优路线、访问顺序、成本或风险 |
| 生产调度 | 甘特图、设备—时间热力图、冲突和空闲区间 |
| 选址与覆盖 | 候选点、最终选址、服务半径和需求覆盖 |
| 网络优化 | 节点、边、容量、流量和瓶颈 |
| 多目标优化 | Pareto 前沿以及最终推荐解的位置 |
| 空间环境与气象 | 预测地图、差值地图或时空演化图 |
| 综合评价 | 对象排序、分层结果和关键指标贡献 |

### 必须包含

- 最终推荐解或关键结果的显式标记；
- 与基准方案或原方案的对照；
- 目标值、成本、收益、误差或覆盖率等核心数值；
- 关键约束是否满足；
- 单位、图例和必要的编号；
- 正文可逐项引用的结果编号或区域名称。

不要把“训练损失下降”或“模型精度较高”当作核心结果图，除非赛题本身只要求模型性能。

## 图 5：预测—真实值与残差联合图

### 目的

同时回答模型是否准确、是否有系统偏差、在哪些区间失败以及误差是否稳定。

### 推荐三面板

- `(a)` 真实值与预测值随时间或样本顺序的对照，可增加预测区间；
- `(b)` 预测值—真实值散点图，增加 `y=x` 参考线；
- `(c)` 残差—预测值或残差—时间图，增加零残差线。

根据任务还可增加残差分布、Q-Q 图、误差累计分布或分组误差箱线图。

### 必须标注

- 明确写出训练集、验证集或独立测试集；
- 样本数及数据时间范围；
- MAE、RMSE、MAPE、R² 等与赛题匹配的指标；
- 零误差线和 `y=x` 参考线；
- 置信区间或预测区间的计算口径；
- 重大异常样本或失效区间。

若赛题不是监督预测任务，可将本图替换为“理论值—仿真值与残差”“回测结果与误差”“约束残差与可行性检查”，不要强行绘制没有真实标签的预测—真实图。

## 图 6：基线与消融比较图（带误差棒）

### 目的

证明所选方法相对于简单方案确有价值，并说明性能提升来自哪些关键步骤，而不是来自一次偶然运行。

### 推荐比较对象

- 最简单且合理的规则或统计基线；
- 常用标准模型；
- 本文完整模型；
- 删除关键模块或约束后的消融模型；
- 必要时加入原方案、官方方案或业务现状。

### 必须包含

- 多次随机划分、交叉验证、Bootstrap 或多场景运行的均值；
- 标准差、标准误或 95% 置信区间，并在图注中说明误差棒含义；
- 样本数、重复次数和数据划分方式；
- 指标方向，如“越低越好”或“越高越好”；
- 相对提升百分比；
- 指标量纲差异过大时使用分面图，避免滥用双纵轴或雷达图。

统计结果由代码自动读取实验汇总文件生成。禁止只画一次运行结果的柱状图，也不要在没有重复实验时伪造误差棒。

## 图 7：灵敏度或鲁棒性图

### 目的

检验参数、输入噪声、场景和约束变化时，主要结论是否保持稳定，并说明推荐方案的适用边界。

### 推荐扰动

- 关键超参数或权重系数；
- 数据噪声、缺失比例或测量误差；
- 需求量、价格、容量、预算或资源上限；
- 初始条件、随机种子或时间窗口；
- 极端场景、设备故障或分布变化。

### 推荐形式

- 单参数性能曲线；
- 双参数热力图或等高线；
- 不同场景的箱线图或误差分布；
- Pareto 前沿；
- 收敛曲线；
- Monte Carlo 结果分布。

### 必须包含

- 基准参数或论文采用参数的位置；
- 合理扰动区间及其依据；
- 可行区间、稳定区间或阈值；
- 结论发生反转或约束失效的位置；
- 每个扰动水平的重复次数；
- 不重新调参的鲁棒性结果与重新调参后的最优结果要明确区分。

不要只展示对方法有利的狭窄参数区间，也不要仅凭一条平滑曲线声称模型“非常稳定”。

## 图 8：与实际场景对应的最终决策图

### 目的

将数学结果转化为可执行、可解释的现实方案，是论文从“算出答案”走向“解决问题”的最后一步。

### 适用形式

- 物流、巡检或交通路线及其执行顺序；
- 生产调度、人员排班和工序流程；
- 供应链、通信、电网或能源网络决策；
- 场站、仓库、医院或服务设施选址；
- 风险分级和应急处置流程；
- 设备、芯片、工厂或资源布局；
- 政策情景下的阶段性实施路线图。

### 必须包含

- 推荐方案及备选方案；
- 执行顺序、时间、节点或区域；
- 关键成本、收益、风险或资源占用；
- 约束和现实边界；
- 从模型输出到实际行动的映射；
- 图注能够概括“为什么推荐该方案”。

若包含真实地图、遥感影像、气象栅格或复杂空间底图，先用 GIS/Python 生成准确底图，再由 Scientific Illustrator 添加可编辑的节点、路线、标注、图例和决策说明。不可用手绘示意图冒充精确地理位置。

### 工具与交付

使用新版 Scientific Illustrator 制作可编辑场景层；如有底图，只允许把不可矢量重建的最小区域作为图片插入，其余文字、路线、箭头、边框和图例均保持可编辑。

可复制给 Codex 的提示词：

```text
[@scientific-illustrator](plugin://scientific-illustrator@scientific-illustrator-tools)
使用新版 Scientific Illustrator，在实时 draw.io 中制作数学建模论文的最终场景决策图。
严格依据我提供的最优解、约束检查和场景信息，把模型输出映射为可执行的节点、路线、时序、布局或处置步骤；
同时展示推荐方案、必要的备选方案、关键成本/收益/风险和现实限制。
如果提供了 GIS 或 Python 生成的底图，只把底图作为最小必要图片区域插入，所有路线、节点、标签、图例和说明均重建为可编辑对象。
逐区域检查位置、连线、编号和数值是否与结果文件一致。完成后保存为 fig8_decision_scenario.drawio，
并导出矢量 PDF 和宽度 2000 px 的 PNG。
```

## 四、统一视觉与导出规范

### 统一视觉

- 全文同一对象或模型保持同一颜色；
- 主色不超过三种，其余使用中性灰；
- 不依赖红绿差异传递唯一信息；
- 正文字号按论文版面缩放后不低于 8 pt；
- 同类图统一线宽、标记大小、图例位置和坐标格式；
- 多面板统一使用 `(a)(b)(c)`，面板顺序与正文叙述一致；
- 坐标轴必须有变量名和单位；
- 最优点、基准线、阈值和可行区间要直接标注；
- 图注应写出主要发现，而不只是重复图名。

### 导出格式

- 流程图、结构图、折线图、散点图和柱状图优先导出 PDF/SVG；
- 位图至少 300 dpi，预览图宽度建议不低于 2000 px；
- 插入论文前在 100% 缩放下检查文字、图例和线条；
- 避免截图、三维柱状图、三维饼图、彩虹色热力图、词云和无误差棒的模型排名图；
- 数据更新后必须重新运行绘图脚本，禁止手工移动数据点来“美化”结果。
