# 图 8 场景决策、部署或交付图：事实依赖与可编辑候选工作流

本指南供正式比赛复用，顺序为**核对场景事实和证据 → 比较模板 → 选择工具 → 三版可编辑候选 → PNG 检查与比较 → 用户确认 → 正式导出**。图 8 可以是执行方案、部署管线、风险处置或结果交付图；不预设地图、泳道、卡片布局或具体绘图工具。内容定位见[八图总指南](figures_guide.md)，数据及导出时序遵守[绘图规范](09_plotting_protocol.md)。

## 0. 列出场景事实与禁止关系

读取题目、交接资料、`results/verified/` 的最终结果、模型冻结或发布记录（若存在）及证据登记表。列出真实输入、输出、模型依赖、执行者或系统、动作、人工复核、约束、风险、时间顺序和 Evidence ID。每条箭头注明是数据流、计算依赖、审批或执行顺序；不把它自动写成因果作用。

推荐解、备选方案、成本收益和地理位置只在赛题与核验结果确实提供时出现。若官方测试没有真实标签，不报告测试误差；发布或交付检查 PASS 只表示检查通过，不代表模型准确率。若存在冻结后唯一发布边界，不画官方测试结果回到训练选模的箭头。聚合输出必须按模型或业务规则生成，不新增独立预测头或其他未经证实的机制。

### 1.3 按场景性质选择并比较

创建对象前实际查看至少三个可编辑模板或有源码的场景图示例，比较节点组织、泳道/分组、路径、图例、语义风险和缩小后的可读性。必须进入仓库查看具体源文件、示例、版本和许可；若不足三个，记录检索范围、关键词和原因。

- **少量节点、单一阅读路径、主要目的是解释执行顺序：**优先查看 diagrams.net 官方示例。
- **多个执行者、人工审核、并行任务、异常事件或回退：**优先查看 BPMN 示例，并明确泳道责任和网关条件。
- **输入条件通过明确规则产生决策动作：**可查看 DMN；决策表必须逐行对应题目、模型或已核验规则。
- **模型需要部署到设备、服务、数据库或业务系统：**优先查看 `mingrammer/diagrams`、PlantUML C4 或 ISA-M；区分“已部署”“建议部署”和“未来扩展”。
- **路线、选址、覆盖、区域分级或空间资源配置：**使用 QGIS/Python 生成准确地图，再参考 MapAction 或 NPS `.qpt` 组织版面。
- **同时存在流程和地图：**以 GIS 图为事实底层，以少量可编辑流程节点和解释框覆盖，不把两个完整复杂模板硬塞进同一画布。

以下情况不能直接套用模板：没有真实执行者却使用泳道、没有规则阈值却使用 DMN、没有空间坐标却绘制精确地图、没有部署证据却使用云服务图标，以及把模型训练流程再次包装成图 8。图 8 必须解释结果如何进入场景，而不是重复图 1。

### 1.4 模板比较记录要求

在 `projects/<project_name>/figures/figure8/template_review.md` 中，针对每个具体候选至少记录：

1. 模板库和具体示例的永久网址、文件路径或提交版本；
2. 实际查看的源文件类型，如 `.drawio`、BPMN/DMN XML、Python、PlantUML 或 QGIS `.qpt`；
3. 当前场景中的执行者、系统、动作、事件、规则、地图层与模板对象的对应关系；
4. 计划借鉴的布局，以及明确不借鉴的原始文字、品牌图标、数字、角色和箭头；
5. 可能造成的错误暗示，如虚构审批、自动化、反馈、云部署、成本收益、地理精度或测试性能；
6. 改造量、可编辑性、许可与署名要求、论文缩小后的可读性；
7. 三个候选方案各自适合的阅读路径，以及选择或放弃的理由。

配色灵感不能单独算一个结构模板。同一个仓库中的三个近似配色版本也不能冒充三个独立候选。

### 1.5 可选绘制后端

根据图形需要选 Draw.io、Penpot、PowerPoint/WPS、OpenTikZ、GIS/Python 或其他合适后端，并记录理由。地图或科学影像由可靠数据与专业工具生成，保留坐标与来源；能用原生对象绘制的文字、路线、箭头、边框和图例保持可编辑，不把整图压成位图。

## 2. 制作三版可编辑候选

在同一份事实清单上制作 A/B/C 三版，每版保存独立可编辑源或原生 Board，并导出 PNG。可尝试不同的分组与阅读顺序，但模型名称、数据依赖、发布边界、风险动作及证据口径必须相同。每版至少执行一轮“绘制 → PNG 检查 → 对象级修正 → 再导出”，重新打开源文件，核对文本、箭头方向、线条交叉、图例、灰度、论文宽度下的字号与可编辑性。

在 `candidate_comparison.md` 根据实际 PNG 比较三版的信息传递、错误语义风险、操作路径、可编辑性及缩小后可读性，给出推荐顺序并交给用户确认。确认前，单图目录中的候选图像产物只保留原生源与 PNG；必要的数据、模板、证据和比较记录照常保存。

## 3. 用户确认后正式导出

用户明确选定最终版后，仅为该版生成 SVG/PDF，核对矢量对象、字体、裁切、画布、图层可编辑性和最终论文版面。若导出导致整图栅格化，修正导出路径并重新检查；未入选候选继续只保留源文件和 PNG。`delivery.md` 记录证据文件、工具与模板、原生源位置、用户确认、正式导出方式和未解决限制。

2024 B 题的[绘图数据](../projects/rehearsal_2024_B/results/verified/figure_data/fig08_deployment_decision.json)、[模板评审](../projects/rehearsal_2024_B/figures/figure8/template_review.md)和[候选比较](../projects/rehearsal_2024_B/figures/figure8/candidate_comparison.md)展示冻结模型、发布边界、输出依赖与风险复核；证据包括 E-FREEZE-001、E-Q2-001、E-Q3-CONFIG-001、E-RELEASE-001。该实例使用 Draw.io 并已有候选矢量文件，均不成为其他赛题的固定工具或新流程的候选导出要求。
