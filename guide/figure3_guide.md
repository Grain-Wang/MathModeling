# 图 3 关键变量关系或模型结构图：模板比较与可编辑候选工作流

本指南供正式比赛复用，顺序为**核对事实与连接 → 比较模板 → 用户选择结构 → 选择工具并制作可编辑候选 → PNG 视觉验收 → 用户确认最终版 → SVG/PDF 正式导出**。不预设 Draw.io、Penpot、PowerPoint/WPS、OpenTikZ 或其他具体绘图工具；模板、版式、配色和后端由赛题关系与可编辑交付需求决定。内容边界见[八图总指南](figures_guide.md)，证据与导出阶段遵守[绘图规范](09_plotting_protocol.md)。

## 0. 整理可核对的结构规格

读取题目、项目交接资料、模型公式与接口、实现代码、`results/verified/` 和结果登记表。写明图要解释的关系及证据，列出节点、公式、约束、分支条件、连接方向、箭头含义和禁止关系；区分数据流、计算依赖、选择条件与尚待验证的假设。信息流箭头不自动代表因果作用。

绘图前记录工具及选择理由。Draw.io、Penpot、PowerPoint/WPS、OpenTikZ 或其他可编辑后端均可按任务选用。相关系数、散点、SHAP 等数值图由数据脚本生成，不手工摆点。

**进入下一步的条件：**每个节点、公式和连接都能回指事实源；不清楚的关系先核对模型资料，不靠模板补全。

### 1.3 按真实拓扑选择并比较

创建图形对象前，实际查阅至少三个与本题拓扑相关的可编辑模板或有源码的结构图示例，查看节点、连线、分组或源代码，而非只看预览。必须进入仓库查看具体源文件、示例和许可说明；若不足三个，记录检索范围、关键词和原因。

- **输入变量—状态变量—输出变量、公式模块或算法阶段：**优先查看 OpenTikZ、diagrams.net 和 sci-box 的框架模板。
- **因果假设、混杂、调整集或结构因果模型：**优先查看 ggdag；在 `template_review.md` 中写明每条因果边的理论、文献或实验依据。
- **真实节点—边网络：**优先查看 tikz-network/network2tikz；边权、方向、容量和层级必须来自数据或模型定义。
- **模型由多个子系统、外部参与者和接口组成：**可查看 C4 Draw.io；先证明这些层级确实存在，再决定是否采用系统边界。
- **结构较简单且需要高频人工修改：**可以从 diagrams.net 官方示例起步，比较后选择空白画布通常比强行套复杂模板更合适。

以下内容不能作为图 3 的结构模板：只有配色截图而无源文件的图片、无法识别节点与连接的宣传图、与本题拓扑不同但视觉华丽的架构图，以及把相关性或特征重要性伪装成因果关系的示意图。

### 1.4 模板比较记录要求

在 `projects/<project_name>/figures/figure3/template_review.md` 中，针对每个具体候选至少记录：

1. 模板库和具体示例的永久网址、文件路径或提交版本；
2. 实际查看的源文件类型，如 `.drawio`、`.tex`、R/Python 脚本或 XML 形状库；
3. 与当前节点、层级、分支、反馈和汇合结构的对应关系；
4. 计划借鉴的布局，以及明确不借鉴的原始文字、数字、图标、箭头和配色；
5. 可能造成的错误语义，如无依据的因果边、系统边界、反馈、执行顺序或层级；
6. 改造量、可编辑性、许可与署名要求、论文缩小后的可读性；
7. 选择该模板、选择其他模板或改用空白画布的理由。

结构借鉴与配色灵感分别记录，配色截图不能单独计作一个结构模板。给用户一至两个建议结构供选择；用户确定试绘结构后再绘制。

## 2. 制作可编辑候选并用 PNG 验收

按选定结构分别建图，保留各自原生源文件或可编辑工程；使用 Penpot 时记录文件、页面和 Board 链接，不在指南或交付记录中写入 MCP 密钥。文字、形状、分组、公式和连接线应保持可编辑，参考模板不能作为整图位图充当成品。若需要从一种工具转入另一种工具，候选阶段用 PNG 作锁定参考，再以目标工具的原生对象重建。

每版只导出 PNG 预览，至少完成两轮“绘制 → PNG 检查 → 对象级修正 → 再次检查”。重新打开源文件或 Board，核对可编辑性、公式、名称、箭头方向、条件和证据边界；检查截字、重叠、穿过节点的连线、无意义交叉、图例、灰度和论文宽度下的可读性。分支、回退、汇合与聚合不得因模板原有箭头而改变真实顺序。

若有多个候选，在 `candidate_comparison.md` 比较实际 PNG、源文件编辑成本和内容完整性，给出推荐及限制，再把候选交给用户确认最终版本。确认前，单图目录中的图像产物只保留源文件与 PNG，不生成或保留 SVG/PDF。

## 3. 最终导出与交付

用户明确确认版本后，才为该版本导出 SVG/PDF，并检查矢量性、字体、裁切、线条和最终论文版面；异常时修改原生源，再重新导出并复核。未入选候选继续只保留源文件和 PNG。若选用多工具流程，正式图必须来自最终编辑源，不能把参考位图当作矢量成品。

文件统一放在 `projects/<project_name>/figures/figure3/`：模板比较、各候选原生源与 PNG、图注、`delivery.md`，以及确认后选定版的 SVG/PDF；多候选时附比较记录。`delivery.md` 记录证据文件或 Evidence ID、工具与模板选择、两轮检查、用户确认、正式导出检查和未解决问题。

2024 B 题的[模板与 Draw.io 候选](../projects/rehearsal_2024_B/figures/figure3/fig03_template_candidates.md)及[Penpot 双风格比较](../projects/rehearsal_2024_B/figures/figure3/penpot_style_compare.md)可用于核对做法；其中的工具、C/D 模板、E/F 版本、模型公式、数字和配色均不是其他赛题的预设。该实例既有导出文件保留历史状态，不代表新指南要求候选阶段生成矢量文件。
